# Resource identifiers

Relay uses UUIDs for database records and short typed IDs for dynamically
allocated Kubernetes resources. Display names never supply entropy or become
primary keys.

## Short identifiers

The shared Node-only entry point is `@tali/contracts/resource-identity`.
Every generated ID has **16 characters total**: `t`, a resource-type letter,
`-`, and 13 lowercase Base32 characters. The suffix is the first 65 bits of
SHA-256, encoded with `abcdefghijklmnopqrstuvwxyz234567`. New allocations hash
a random UUID. Resources derived from an existing identity hash that complete
identity, without truncating the input. A canonical typed ID passes through
unchanged.

| Resource | Previous rule | Current rule |
| --- | --- | --- |
| Project primary key | Name + 8 UUID characters; briefly `tp-` + 16 Base32 characters | `tp-` + 13 Base32 characters |
| Project Namespace / OpenShell Workspace | Separate hash of Project ID | Same as Project ID |
| Supervisor Instance | UUID | `ti-` + 13 Base32 characters |
| Supervisor Sandbox | `i-` + 17 base36 characters derived from UUID | Same as Instance ID |
| Managed A2A / developed Agent Instance | UUID or asynchronous operation UUID | `ti-` + 13 Base32 characters |
| Managed A2A Deployment and Service | `tali-a2a-` + 16 hex characters | Same as Instance ID |
| Developed Agent Deployment, Service, ConfigMap and runtime Secret | `tali-expert-` + 16 hex characters | Same as Instance ID; these objects describe one Instance |
| Credential Secret in Control namespace | `tali-secret-` + truncated scope and resource names + 10 hex characters | `ts-` + 13 Base32 characters derived from `[scope, resourceId]` |
| OpenShell inference / Bridge credential Provider | `tali-<sandbox>` / `tali-<sandbox>-bridge` | `tc-` + 13 Base32 characters derived from `[sandboxId, purpose]` |

`p` means Project, `i` Instance, `s` Secret, and `c` Credential. Credential
purposes and Secret scopes are included in the hash input to prevent different
resources from sharing a name. Hash names are identifiers, not authentication
credentials.

Persist the ID before queueing provisioning. Worker retries derive an Instance
ID from the same operation UUID, or reuse an already persisted Instance ID.
They must not allocate a new ID on each attempt. Database uniqueness and
Kubernetes ownership checks remain in force.

## Database-only identities

| Resource | Previous rule | Current rule |
| --- | --- | --- |
| Department | Client-selected name/slug | Server-generated UUID |
| User, authentication Session, Account and Verification | Authentication library ID; some UUIDs | UUID generated by Relay's authentication configuration |
| Project invitation | `invite-<UUID>` | UUID |
| Registered Agent catalogue entry | Name + 8 UUID characters, or operation UUID | UUID; asynchronous operation UUID is reused on retry |
| External A2A Instance (no managed workload) | UUID | UUID |
| User-created Skill, MCP connection and Vector Database | Name + 8 UUID characters | UUID |
| Vector Document | File name + 8 UUID characters | UUID |
| Custom runtime policy | Name + 8 UUID characters | UUID |
| Access policy, model routing and routing binding | UUID | UUID |
| Provider account and model deployment | UUID | UUID |
| Developed Agent definition, released Version, test run and Version artifact | UUID | UUID |
| Durable Memory, binding, outbox, curation event and experience projection | UUID | UUID |
| Vector folder and ingestion job | UUID | UUID |
| Resource operation, lifecycle operation, queue job, audit event, notification, terminal/log session | UUID | UUID |
| External identity role binding | UUID | UUID |

An Agent definition/Version is a database object, distinct from an instantiated
Kubernetes workload. Its UUID does not become the Deployment name.

## Identifiers with other semantics

- Built-in Role/Capability codes, built-in catalogue IDs, default-policy IDs,
  and singleton keys such as `platform` are stable codes, not new allocations.
- Compound primary keys retain their component IDs (membership, revision,
  sequence, tool names, and resource bindings).
- Provider-issued IDs, OIDC subjects, model names, A2A messages and external
  run IDs belong to their respective protocols. Relay does not rewrite them.
- Content digests, cost reconciliation fingerprints, trace/span IDs, and
  deterministic ingestion/deduplication keys keep their existing formats.
  Truncating these as resource names would change their integrity or deduplication
  semantics.
- Fixed component names (`tali-agent-runtime-bridge`, Helm release names,
  OpenShell Gateway Service prefixes) are service-discovery configuration.
  They are not generated resource IDs.
- Kubernetes and OpenShell generate child names: a Deployment adds ReplicaSet
  and Pod suffixes; OpenShell combines Workspace and Sandbox for a Pod and
  prefixes workspace PVC names. **16 characters applies to Relay's base ID**,
  not those controller-generated child names.

No database schema migration is needed for new short runtime IDs: Project and
Instance keys are text. UUID-typed Memory and developed Agent definition tables
remain UUID-typed. Existing persisted runtime targets and payload references
must be reset together before rebuilding old workloads; deleting a Namespace
alone does not rename its database mapping.
